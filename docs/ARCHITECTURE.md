# 架构与验证边界

## 界面与主进程

React UI 通过受限 preload IPC 请求 Electron 主进程。主进程验证参数，管理 APK 网络请求、游客上下文、账号会话、偏好、观看记录、诊断与本机媒体 capability。渲染端保持 contextIsolation、sandbox、webSecurity，不启用 Node integration。

APK 仍需要 ARM JNI 签名/加密，Java worker 用 unidbg 执行用户提供的原库。这个依赖不能用原生 Windows DLL 直接替代，公开源码也不能生成专有库；用户必须准备本地运行资源。JNI 适配器源码包含运行回调，不包含最初的调查入口或捕获的身份。

## 真实目录逻辑

首页、搜索、排行和探索使用原 APK 服务契约。探索筛选调用 `POST /reading/distribution/category/landpage/v1/`，读取 `selector_rows`、`video_data`、session/offset 与 `has_more`。客户端不固定主题/角色列表，体裁切换可以动态增删行。请求发出前立即更新选择状态，结果只接受最新有效请求。

公共目录保留服务器顺序，系列分组只采用官方关联信息。UI 的卡片/列表切换不重新排序、不写入默认偏好。默认排列只由设置更新，初始值为原卡片。

## 媒体

经允许的播放模型转换为本机媒体 capability，FFmpeg 独立子进程通过流处理视频。解码密钥和来源地址不写入本地记录或诊断日志。官方的锁定/不可播放状态保留。没有账户权限的内容不通过源码取消限制。

视频切换先响应翻动，不等网络完成；进度跳转时保留已解码画面，收到新帧后继续播放。详情与选集共享目录组件，加载时保持最终弹窗尺寸。

## 2.3.8 连续播放管线

默认无感连播使用同一个 video、MediaSource 和 SourceBuffer。FFmpeg 输出 H.264 + 48kHz 双声道 FLAC，避免每集 AAC 编码重启产生的预滚；MP4 片段解析器校验轨道、样本长度和偏移，按音频实际采样数对齐视频尾帧及下一集时间戳。保持原播放模型的完整时长，不剪掉片头片尾，也不用集间淡化或额外静音掩盖间隙。

自然换集只更新章节对应的集数、本集进度和记录。全局媒体时钟继续增长，video 与 blob 源不变；手动跳转、选集或清晰度变化走替换流程。取消和关闭会终止旧读取，过期回调不能覆盖新选择，原授权状态保留。

积极缓冲的前向时间目标约 75 秒，普通模式约 35 秒，最多预取相邻下一集；串行清理旧媒体区间并遵守原生任务／队列上限。网络或解码失败沿用最多两次的恢复预算，主动暂停不自动续播。

日志白名单分别保存本集秒数与连续时间线秒数，不包含媒体 URL 或密钥。CSP 仅允许既有本机媒体 fetch 和 blob 媒体，webSecurity 保持开启。

## 数据

偏好和本地追剧/记录存储在 Electron 的当前用户数据目录。账号凭据在 Windows 使用系统加密；导出日志采用字段白名单，不导出原始请求、Cookie、手机号、验证码或播放密钥。

## 验证来源与日期

2.3.4 的历史 Windows 工作版通过 87 项测试。2026-10-25 的 2.3.8 工作版为 109 项测试、108 通过、1 项 HEIC 跳过，并通过完整隐藏静音在线回归；三次真实集间接点保持同一视频源，没有 play/pause/load/waiting/ended。

独立的合成音频 AudioWorklet 检查两处接点新增／丢失采样均为 0，使用精确到单采样的非整毫秒片段，中间更改画面尺寸和帧率。不是扬声器听测，也不是对所有片源的保证。脚本见 `scripts/audio-pcm-check.cjs`，公开源码同步的本地检查日期和数量见 [更新记录](CHANGELOG.md)。

此处保留历史范围，不上传包含真实剧集画面、个人路径或账号数据的原始截图／日志。本次源码同步没有重新声称 11 月的实际服务播放已通过。

公开版测试用合成目录响应替代捕获响应，以可选本地 HEIC 样本替代原图像样本；原生库、JRE、FFmpeg 等不随 GitHub 源码发布。因此 GitHub CI 的通过只证明公开源码构建和离线合同验证，不等于验证实际服务播放。

真实账号登录、云记录同步尚存在兼容性问题，不能用本地记录或合成测试结果表示它们已经成功。macOS 历史代码保留用于诊断，当前正式构建与支持范围只有 Windows x64。
